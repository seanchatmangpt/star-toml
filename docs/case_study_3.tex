\section*{Setup}

\textbf{Crate:} \texttt{cargo-cicd} (continuous integration / publish gate)

\textbf{Configuration File:} \texttt{cicd.toml}
\begin{lstlisting}[language=toml]
[publish]
crate_name = "star-toml"
version = "26.6.30"
registry = "crates.io"

[toolchain]
channel = "nightly"
date = "2025-01-01"  # This version does not exist locally
msrv = "1.70"

[gates]
require_clippy_passing = true
require_tests_passing = true
require_audit_clean = true
publish_on_success = true
\end{lstlisting}

\textbf{The Bug:} The cargo publish gate must compile the crate against the specified toolchain to verify it meets the minimum supported Rust version (MSRV). The \texttt{cicd.toml} specifies \texttt{nightly-2025-01-01}, but:

\begin{enumerate}
  \item User has only \texttt{stable} and \texttt{nightly-2025-06-20} installed
  \item Publish gate tries to run \texttt{rustup toolchain install nightly-2025-01-01}; succeeds (downloads from internet)
  \item Build executes against \texttt{nightly-2025-01-01} (now installed on-demand)
  \item Crate compiles cleanly; all gates pass
  \item Crate is published to crates.io
  \item \emph{Later:} User on a different machine runs the published crate against \texttt{stable-1.70}
  \item Code relies on an API that was stabilized after 2025-01-01 → compilation fails
  \item MSRV claim in the published crate is fraudulent
\end{enumerate}

This is a \emph{silent} configuration error: the toolchain exists (can be installed), but differs from what was intended to be tested.

\section*{Without Admission}

\textbf{Error Trace (what \emph{would} happen):}

\begin{lstlisting}
// In publish_gate.rs, line 456
pub async fn validate_msrv(config: &CicdConfig) -> Result<()> {
  let toolchain_spec = &config.toolchain;
  let channel = &toolchain_spec.channel;
  let date = &toolchain_spec.date;

  // Construct toolchain name: "nightly-2025-01-01"
  let tc_name = format!("{}-{}", channel, date);

  // Try to install (succeeds if internet available)
  let output = Command::new("rustup")
    .args(&["toolchain", "install", &tc_name])
    .output()?;

  if !output.status.success() {
    // Error only if toolchain doesn't exist on servers
    return Err(format!("Toolchain not found: {}", tc_name).into());
  }

  // Set default toolchain
  Command::new("rustup")
    .args(&["default", &tc_name])
    .output()?;

  // Compile crate
  let build = Command::new("cargo")
    .args(&["build", "--release"])
    .output()?;

  if !build.status.success() {
    return Err("Build failed".into());
  }

  // All gates pass; crate is ready to publish
  Ok(())
}

  publish_to_crates_io(config).await?; // ← CRATE PUBLISHED

\textbf{Why This Is Bad:}
\begin{itemize}
  \item Configuration is syntactically valid
  \item Toolchain \emph{does} exist (can be downloaded)
  \item All automated tests pass (they run against nightly, which is more permissive)
  \item The crate is published with false MSRV claim
  \item End users encounter compilation failures
  \item No audit trail of which toolchain was actually used during publish
  \item Semantic invariant (toolchain must be \emph{the local user's installed version, not internet-fetch-on-demand}) is not validated
\end{itemize}

\section*{With Admission}

The \texttt{cargo-cicd} config struct validates that the toolchain is \emph{locally available}:

\begin{lstlisting}
#[derive(Debug, Deserialize)]
struct ToolchainSpec {
  channel: String,      // "stable", "beta", "nightly"
  date: String,         // "YYYY-MM-DD" or empty for latest
  msrv: String,         // "1.70", "1.75", etc.
}

#[derive(Debug, Deserialize)]
struct PublishConfig {
  crate_name: String,
  version: String,
  registry: String,
}

#[derive(Debug, Deserialize)]
struct GatesConfig {
  require_clippy_passing: bool,
  require_tests_passing: bool,
  require_audit_clean: bool,
  publish_on_success: bool,
}

#[derive(Debug, Deserialize)]
struct CicdConfig {
  publish: PublishConfig,
  toolchain: ToolchainSpec,
  gates: GatesConfig,
}

impl Validate for ToolchainSpec {
  fn validate(&self, v: &mut Validator) {
    v.check_non_empty("channel", &self.channel);
    v.check_one_of(
      "channel",
      &self.channel,
      &["stable", "beta", "nightly"],
    );

    // Validate MSRV format
    v.check_predicate("msrv", &self.msrv, |msrv| {
      // Must be "major.minor" format, e.g., "1.70"
      let parts: Vec<&str> = msrv.split('.').collect();
      parts.len() == 2 && parts.iter().all(|p| p.parse::<u32>().is_ok())
    });

    // NEW: Check that toolchain exists locally
    if !self.date.is_empty() {
      let tc_name = format!("{}-{}", self.channel, self.date);
      match self.check_toolchain_exists(&tc_name) {
        Ok(true) => {
          // Toolchain is installed locally
        }
        Ok(false) => {
          v.error_with(
            "date",
            &self.date,
            star_toml::ErrorKind::NotOneOf,
            format!(
              "Toolchain '{}' not installed. \
               Run: rustup toolchain install {}",
              tc_name, tc_name
            ),
          );
        }
        Err(e) => {
          v.error_with(
            "date",
            &self.date,
            star_toml::ErrorKind::Validation,
            format!("Cannot verify toolchain: {}", e),
          );
        }
      }
    }
  }
}

impl ToolchainSpec {
  fn check_toolchain_exists(&self, tc_name: &str) -> Result<bool> {
    let output = Command::new("rustup")
      .args(&["toolchain", "list"])
      .output()?;

    if !output.status.success() {
      return Err("rustup toolchain list failed".into());
    }

    let stdout = String::from_utf8(output.stdout)?;
    Ok(stdout.lines().any(|line| line.contains(tc_name)))
  }
}

impl Validate for CicdConfig {
  fn validate(&self, v: &mut Validator) {
    v.field("publish", |v| self.publish.validate(v));
    v.field("toolchain", |v| self.toolchain.validate(v));
    v.field("gates", |v| self.gates.validate(v));

    // Cross-field constraint: if publish_on_success=true,
    // all gates must be enabled
    if self.gates.publish_on_success {
      v.check_consistent(
        "gates",
        self.gates.require_clippy_passing
          && self.gates.require_tests_passing
          && self.gates.require_audit_clean,
        "If publish_on_success=true, all gate checks must be enabled",
      );
    }
  }
}
\end{lstlisting}

\textbf{Validation Failure (what happens with admission):}

\begin{lstlisting}
match TrustedLoader::new()
  .layer_file("cicd.toml")
  .load_admitted::<CicdConfig>()
{
  Ok(admitted) => { /* never reached */ },
  Err(e) => {
    // ValidationErrors::
    // [ERROR] toolchain.date
    //   code: not_one_of (or validation_failed)
    //   value: "2025-01-01"
    //   reason: Toolchain 'nightly-2025-01-01' not installed.
    //           Run: rustup toolchain install nightly-2025-01-01
    //   severity: Fatal
    //   location: cicd.toml:6
    //
    // Admission Refused (q_config = 0)

    // Action: Developer sees this, decides:
    // Option A: Install the toolchain
    //   $ rustup toolchain install nightly-2025-01-01
    // Option B: Use a toolchain they have
    //   Update cicd.toml: date = "2025-06-20"
    //
    // Either way, the config is now honest about the toolchain.
  }
}
\end{lstlisting}

\textbf{Prevention Mechanism:}
\begin{itemize}
  \item \textbf{Check Type:} Custom predicate: \texttt{v.check\_predicate("date", ..., check\_toolchain\_exists)}
  \item \textbf{Error Code:} \texttt{not\_one\_of} (toolchain version not in the set of installed toolchains)
  \item \textbf{Severity:} \texttt{Fatal} (admission refuses if toolchain unavailable)
  \item \textbf{Fired at:} Load time, before any CI gate runs
  \item \textbf{Guarantee:} If \texttt{AdmittedConfig<CicdConfig>} exists, the specified toolchain is installed on this machine
  \item \textbf{Side Effect:} Validation check shells out to \texttt{rustup toolchain list}; this is the \emph{only} I/O during config admission
\end{itemize}

\section*{Summary}

Without admission, a CI configuration that specified a non-existent (or outdated) toolchain would silently be fetched from the internet, causing the published crate to be tested against a different Rust version than intended. This resulted in false MSRV claims and compilation failures for end users. With admission, the validation layer checks that the specified toolchain is locally available (via \texttt{rustup toolchain list}), refusing admission if a mismatch exists. The witness proves which exact toolchain was used to validate the crate before publishing, providing full traceability and preventing fraudulent MSRV claims.
