# cargo-cicd: Product Requirements Document (PRD)

## Vision

Make Cargo the operational substrate for software engineering.

`cargo-cicd` transforms operational knowledge from tribal process into admitted, executable, receipt-bound law. The system maximizes development freedom while maximizing production impossibility.

---

## Mission

Replace CI/CD workflow orchestration with release-law execution.

- **Development Freedom**: Developers and coding agents should be free to explore during development.
- **Production Safety**: Production environments should refuse states that violate declared operational law.

---

## Product Position

`cargo-cicd` is **not**:
* A CI vendor
* A workflow engine
* A GitHub Actions generator
* A cargo-make replacement
* A shell wrapper
* Another deployment dashboard

`cargo-cicd` **is**:
* An operational substrate
* A release-law executor
* A production admission engine
* An agent control plane
* A deployment orchestration authority
* A receipt generation engine

---

## Product Principles

### Principle 1: Development friction approaches zero
Coding agents should be able to:
* Repair
* Regenerate
* Classify
* Execute
* Explain
without unnecessary human intervention.

### Principle 2: Production mistakes approach impossibility
The system should convert as many production failures as possible into impossible states. Remaining risks become:
* Improbable
* Bounded
* Diagnosable
* Receipted

### Principle 3: Cargo owns operational authority
Everything executes through Cargo. `just` acts merely as an outside-world actuator.

### Principle 4: External systems produce evidence
Only `cargo-cicd` produces standing.

## Security Philosophy

Do not merely detect attacks; harvest impossible states.

| Class | Examples |
|---|---|
| **Impossible** | Unsigned production config, raw production TOML, version drift, stale release artifacts, verifier bypass, receipt omission |
| **Improbable** | Forged release receipts, forged sealed configuration |
| **Bounded** | Business logic, authorization policy, operational key management |
