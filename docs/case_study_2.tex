\section*{Setup}

\textbf{Crate:} \texttt{chicago-tdd-tools} (test harness orchestration)

\textbf{Configuration File:} \texttt{test-workers.toml}
\begin{lstlisting}[language=toml]
[worker_pool]
name = "integration-tests"
job_count = 0         # INVALID: must be > 0 (PositiveUsize)
timeout_sec = 30
worker_type = "isolated"
isolation_level = "process"
\end{lstlisting}

\textbf{The Bug:} The test harness orchestrates parallel test execution across a pool of isolated worker processes. The \texttt{job\_count} field specifies how many concurrent workers can execute. A value of \texttt{0} violates the semantic invariant: you cannot spawn a zero-sized worker pool. Without admission:

\begin{enumerate}
  \item Config loads silently (TOML is valid, serde deserializes \texttt{0} as \texttt{u16})
  \item Test harness bootstraps; enters the worker pool initialization phase
  \item Worker loop tries to allocate 0 threads: \texttt{std::thread::Builder::spawn()} succeeds (allocates nothing)
  \item First test calls \texttt{pool.execute(closure)}, which panics:
  \begin{Verbatim}
  thread 'main' panicked at 'attempt to assign to closed pool'
  \end{Verbatim}
  \item Test binary crashes during fixture setup (before any test code runs)
  \item CI marks job as \texttt{ABORTED}, not \texttt{FAIL}, losing test signal
\end{enumerate}

\section*{Without Admission}

\textbf{Error Trace (what \emph{would} happen):}

\begin{lstlisting}

\textbf{Why This Is Bad:}
\begin{itemize}
  \item Configuration is syntactically correct
  \item Panic occurs \emph{during test setup}, before any test executes
  \item The panic message \texttt{"attempt to assign to closed pool"} is opaque (does not mention config)
  \item CI infrastructure receives \texttt{SIGABRT}, marks job as \texttt{ABORTED} instead of \texttt{FAILED}
  \item Developer must dig through test harness logs to realize the config was invalid
  \item Semantic invariant (\texttt{PositiveUsize}) is embedded in the pool's runtime logic, not visible in config schema
\end{itemize}

\section*{With Admission}

The \texttt{chicago-tdd-tools} config struct enforces the semantic invariant via \texttt{newtype}:

\begin{lstlisting}
/// A positive integer, guaranteed > 0 by the type system.
#[derive(Debug, Clone, Copy, Deserialize)]
pub struct PositiveUsize(u16);

impl PositiveUsize {
  /// Constructor: returns None if value == 0.
  pub fn new(value: u16) -> Option<Self> {
    if value > 0 {
      Some(PositiveUsize(value))
    } else {
      None
    }
  }

  pub fn get(self) -> u16 {
    self.0
  }
}

#[derive(Debug, Deserialize)]
struct WorkerPoolConfig {
  name: String,
  job_count: u16,  // ← Raw field, validated before conversion
  timeout_sec: u64,
  worker_type: String,
  isolation_level: String,
}

impl Validate for WorkerPoolConfig {
  fn validate(&self, v: &mut Validator) {
    v.check_non_empty("name", &self.name);

    // PositiveUsize constraint: must be > 0
    if self.job_count == 0 {
      v.error_with(
        "job_count",
        &self.job_count.to_string(),
        star_toml::ErrorKind::OutOfRange,
        "job_count must be > 0 (PositiveUsize)",
      );
    }

    v.check_range("timeout_sec", self.timeout_sec, 1..=3600);
    v.check_one_of(
      "worker_type",
      &self.worker_type,
      &["isolated", "threaded", "async"],
    );
    v.check_one_of(
      "isolation_level",
      &self.isolation_level,
      &["process", "thread", "none"],
    );
  }
}
\end{lstlisting}

\textbf{Validation Failure (what happens with admission):}

\begin{lstlisting}

\textbf{Prevention Mechanism:}
\begin{itemize}
  \item \textbf{Check Type:} Custom predicate: \texttt{v.check\_predicate("job\_count", cfg.job\_count, |j| j > 0)}
  \item \textbf{Error Code:} \texttt{out\_of\_range} (semantic meaning: value outside the domain of PositiveUsize)
  \item \textbf{Severity:} \texttt{Fatal} (admission refuses)
  \item \textbf{Fired at:} Load time, before \texttt{WorkerPool::new()}
  \item \textbf{Guarantee:} If \texttt{AdmittedConfig<WorkerPoolConfig>} exists, \texttt{config.job\_count > 0}
\end{itemize}

\section*{Summary}

Without admission, a zero-valued \texttt{job\_count} silently created a phantom worker pool that would panic the moment the test harness tried to execute work. The panic occurred outside the test framework, making it appear as a harness crash rather than a config error. With admission, the \texttt{PositiveUsize} semantic invariant is validated at load time via a predicate check, refusing admission and printing a clear repair hint before the test infrastructure even starts. The witness proves which worker pool configuration was admitted.
